# Agent Instructions — sekoya-parts

Standing rules for every AI agent working on this repository. The owner's general rules, valid in every project, are in `~/.claude/AGENTS.md`; this file adds the rules specific to this repository and takes precedence where the two conflict. Read this file and the [Architecture Decision Records (ADRs)](docs/adr/README.md) before working; ADRs are the source of truth for technical decisions.

## 1. Project context

- **Sekoya Parts:** a spare-parts e-commerce catalog, built as a personal portfolio project. It demonstrates the **feasibility** of a very large catalog and, since Phase 4, of a demo shop around it.
- **Owner decisions so far:**
  - **Catalog:** about 100,000 products. One product is compatible with up to 1,000,000 appliance models (500,000 or 200,000 if that proves a problem); the other products have few.
  - **Four page templates:** home, category listing, product page, and one page per appliance model. Phase 4 adds brand, information and shop pages (epic #138).
  - **References on the product page:** only the most popular ones are rendered as text, keeping the page under Google's 2 MB crawl limit (enforced by a CI test) and at a PageSpeed score high enough to merge (see Requirements).
  - **Languages:** ten, on one domain under path prefixes: `fr` (the source), `en`, `de`, `es`, `it`, `nl`, `pt`, `pl`, `sv`, `da`.
  - **Content:** twelve showcase products, one per category (owner decision, 2026-11-13), get real descriptions, translated automatically when a product is added; the others use placeholder text (lorem ipsum) in every language.
  - **Translation budget (owner decisions, 2026-11-13):** DeepL's free API allows 1,000,000 characters in total, once, so spend it very conservatively. A translation memory keeps every translation through catalog reloads. The key lives in Vercel's Production, the owner's `.env.local` and a GitHub Actions secret for the live check, never on previews, and no real translation runs on a preview.
  - **Search:** a hosted search engine like Algolia is mandatory. Algolia and the database stay on free tiers unless that severely blocks feasibility; capping search at about 50,000 products is acceptable. One Algolia application holds three indices, sharing its free plan (owner decision, 2026-11-14): Production 45,000 records, Preview and dev 2,000 each, each environment with its own write and search keys restricted to its own index; CI uses a fake Algolia.
  - **Scope:** a demo shop, with prices in euros (owner decision, 2026-11-15, epic #138): the catalog, a cart, a mock checkout and customer accounts, but no real payment, no email sent, and no order ever delivered or charged. Every shop page says it is a demo.
  - **Images:** about 50 original or CC0 images, reused across products and resized at import.
  - **No third-party scripts:** no analytics, chat widget or cookie banner. The server sends no usage data to third parties either, so library telemetry is turned off (owner decision, 2026-11-13; Payload's since #88). This covers the host's own tools: Vercel Web Analytics and Speed Insights are not used (owner decision, 2026-11-17, issue #137).
  - **Requirements:** mobile performance as high as Next.js and current techniques allow. For Phase 4, a page merges into `main` from a median Lighthouse mobile performance of 90, 95 before (owner decision, 2026-11-15, issue #141), and score symbols are 🟢 from 90, 🟡 from 80 and 🔴 below 80. Checked on every commit that changes code (ADR 0004); fine-grained cache invalidation (a price or description change refreshes only that part of a page); full non-regression tests; automatic Vercel deployments for branches and `main`.
  - **Brand:** "Sekoya Parts", with an original design: nothing taken from other sites' names, branding or texts.
  - **Repository:** public from the start, so the code and its decisions can be reviewed. The site is a personal, non-commercial demonstration: nothing is sold, paid or delivered, and it carries no advertising or client work (owner decision, 2026-11-17, issue #204). Hosting stays on Vercel's Hobby plan on that basis, so agents never add payments, advertising or the promotion of a paid service to the deployed site without the owner's decision: that would need a paid plan.
- **Stack:** decided one ADR at a time, listed in the [ADR index](docs/adr/README.md). Accepted so far: Next.js 16 with the App Router and Cache Components (ADR 0001); Vercel's Hobby plan, with search engines limited to a showcase and functions in Frankfurt (ADR 0002; Vercel itself is an owner decision); Node 26 with its bundled npm, TypeScript 7 and Biome (ADR 0003); Vitest, Playwright, Lighthouse CI on Vercel previews and markdownlint-cli2 in GitHub Actions (ADR 0004); PostgreSQL 18 on Neon's free plan in Frankfurt (ADR 0005); Payload 3 inside the Next.js app, with models and compatibility in the project's own tables (ADR 0006); a seeded generator loading the catalog with `COPY`, with names and placeholder text generated at render time (ADR 0007); one `"use cache: remote"` component per page part, tagged per part and refreshed with `revalidateTag(tag, { expire: 0 })`, to be confirmed by experiment 1 (ADR 0008); 1,000 compatible references as text on the product page, set by experiment 2, and numbered reference pages for the rest (ADR 0009); Algolia's free plan in EU West, queried only through the site's server route, with model search in PostgreSQL (ADR 0010); Next.js's own `app/[lang]` routing with translated addresses, the bare domain redirecting to the language last picked in the switch or the browser's language, `hreflang` in each page, a showcase-only sitemap and `robots.txt`, and DeepL's free API for translation (ADR 0011); Tailwind CSS 4, a self-hosted brand font through `next/font`, and images resized at build time by sharp (ADR 0012); the cart in a cookie, with the header's cart count read by a small browser component so the catalog pages stay static output, and shop actions as forms that work without JavaScript (ADR 0013); customer accounts through Payload's authentication in a `customers` collection, after editor-only access rules on every existing collection, signed in by username with no email stored, and deleted 30 days after the last sign-in (ADR 0014). Nothing is implemented before its ADR is accepted.

## 2. Working with the owner

- **Downloads:** standing exception to the general download rule: the Lighthouse reports artifacts of this repository's own GitHub Actions runs are always downloaded without asking, into the session's scratchpad (owner decision, 2026-11-13).
- **Vercel's agent plugin is read, not installed (owner decision, 2026-11-13):** [vercel/vercel-plugin](https://github.com/vercel/vercel-plugin) is not installed, because it needs Bun, sends usage telemetry by default, adds hooks at session start and has a deploy command that bypasses the Git-driven deployments. When a step needs it, read one file from the repository as guidance; the ADRs prevail over it. Useful here:
  - `agents/performance-optimizer.md`: Core Web Vitals, caching, images and fonts, for Lighthouse work;
  - `skills/vercel-firewall/SKILL.md`: firewall rules, rate limiting and bot management, for Bot Protection;
  - `skills/cdn-caching/SKILL.md`: cache hits, stale content and revalidation, for cache invalidation;
  - `skills/react-best-practices/SKILL.md`: React and Next.js performance rules, for reviewing components.
  - Vercel's documentation search, `npx vercel@latest docs search "<query>"`, needs no login, but it downloads the Vercel CLI, so the download rule above applies the first time.
- **Read the Vercel dashboard yourself (owner rule, 2026-11-16):** the owner's Chrome has the Claude in Chrome extension, signed in to Vercel. When a step needs the dashboard (logs, firewall traffic and rules, settings), read it there rather than asking the owner. Changing a setting or a rule still waits for the owner's go, and the owner types any secret.
- **Production checks:** the general "never get the owner blocked" rules apply. On 2026-11-11, an agent testing the production rate-limiting rule sent 310 requests in parallel; Vercel's platform protection challenged the IP address, and a second test of 400 requests sent while still blocked only prolonged the block.
  - Checks of this project's production send the "Agent checks" secret from `.env.local` as the `x-vercel-protection-bypass` header, as on previews: Bot Protection challenges curl (owner decision, 2026-11-14, issue #135). Never in a URL or a reply.

## 3. Quality rules

- **Unhappy paths** include a slow phone or network as well as a fast desktop.
- **Measure the right pages (owner rule, 2026-11-16):** a check that reaches a page through a link, Lighthouse's included, reads the link from the list that holds it (its `data-list` marker), never "the first link" of a page, and verifies that the page it lands on is the expected template, named by `data-template` on its `<main>` (`site/templates.ts`). Lighthouse stops when a measured page is not the template its check names, and `e2e/lighthouse-pages.spec.ts` resolves the workflow's addresses on every CI run. Every new template gets its name there. Before asking for a merge, read the addresses in the Lighthouse comment, not only its scores.
- **Automate repeatable steps (owner rule):** when planning a check, a test or an environment, work out what must happen again on each preview, deployment, database reset or run, and automate it from the start, with secrets per environment. Never plan a recurring manual step for the owner, and never use a default or committed password.
- **Waiting on a pull request's CI:** the background watch watches the merge state (`CLEAN`, or a failed check) rather than only the checks already reported, since the required "Lighthouse" check appears only after Vercel deploys. A background watch is not polling.
- **Pushing during CI (owner rule, 2026-11-14):** push a code fix as soon as an early check fails, without waiting for Lighthouse: a code push cancels the older commits' CI and Lighthouse runs. A documentation-only push may go up at any time: CI never lets it interrupt a running check (issue #123, ADR 0004).

## 4. Documentation

- **Docs layout:** `docs/adr/` (one ADR per significant choice, indexed in [docs/adr/README.md](docs/adr/README.md)), `docs/specs/` (feature specs, created when needed), `docs/experiments/` (one report per experiment, with its setup, results and conclusion), `docs/development.md` (running the site and its tests locally), and [docs/roadmap.md](docs/roadmap.md) (a summary of the epics and their issues).

## 5. Git and GitHub

- Repository `sekoya-solutions/sekoya-parts` (public). Branch protection on `main`: a pull request is required, for admins too; only squash merges are allowed, and merged branches are deleted. Required CI checks are added once CI exists.
- **Worktrees (owner rule, 2026-11-16):** the general one-worktree-per-session rule comes from issue #174. Each new worktree gets its own dependencies with `npm ci` (owner decision, 2026-11-16): a `node_modules` linked to the main checkout makes Turbopack refuse to build, so the build and the end-to-end tests could not run locally. About 1.2 GB per worktree, mostly copied from npm's cache, freed when the worktree is removed. It also gets a `.tools` folder of its own holding three junctions, `node`, `pgsql` and `ms-playwright`, to the main checkout's `.tools` (issue #209): `npm run test:local` and `npm run test:e2e:local` find their tools in the checkout they run in, and keep their throwaway clusters in the worktree.
  - **A worktree's preview (issue #193):** the preview tool reads only the main checkout's `.claude/launch.json` and starts every command in the main checkout, whichever folder the session works in. A worktree session runs `npm run preview:add` in its worktree, which also copies the main checkout's `.env.local` there when it has none, and starts the entry that command prints with `preview_start`. The entry runs that worktree's `scripts/preview.ts` (Payload's migrations, then `next dev`) on its own port from 3002, so previews of different worktrees run side by side, and each run of the command drops the entries of removed worktrees. Stop the preview before `npm run test:e2e:local`, which deletes `.next` on Windows and stops while a development server holds it.
- **Labels:** besides the `type:` and `area:` labels, `accessibility` and the triage labels (`duplicate`, `invalid`, `question`, `wontfix`) can be added.
- **Board:** the [Sekoya Parts board](https://github.com/users/sekoya-solutions/projects/3).
